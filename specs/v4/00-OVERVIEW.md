# 00 — Overview (V4 changes)

> Delta file. Baseline: `../v1/00-OVERVIEW.md` plus V2 and V3 deltas. Source spec: `cashier-business-owner` V4.

Each user may stay signed in on at most 2 devices at the same time, with one session per device: signing in again on a device replaces that device's previous session.

## Glossary additions

- **Active_Session**: A Session that has been established, has not reached its expiry time under the Day_Boundary rule, and has not been revoked.
- **Concurrent_Session_Limit**: The maximum number of Active_Sessions a single user may hold at the same time, fixed at 2, with at most 1 Active_Session per Device_Identifier.
- **Session_Revocation**: The System action that ends an Active_Session before its expiry time, either because of the Concurrent_Session_Limit (reason `CONCURRENT_LIMIT`) or because of a Device_Replacement (reason `DEVICE_REPLACED`).
- **Revoked_Session**: A Session that has been ended by Session_Revocation and is no longer an Active_Session.
- **Device_Identifier**: A persistent random identifier generated by the client and stored on the device (browser storage for the Dashboard, installation storage for the POS_Interface) and submitted with each login. It is scoped to a user and is not used as proof of identity or for authorisation.
- **Device**: A client installation identified by one Device_Identifier.
- **Device_Replacement**: The Session_Revocation of a user's Active_Session on a Device when the same user authenticates again with that Device's Device_Identifier.

## Data model changes

- `Session` gains `id`, `deviceId`, `deviceLabel` (informational), `revokedAt`, `revokedReason` (`CONCURRENT_LIMIT` | `DEVICE_REPLACED`), `revokedBySessionId`.
- Sessions are persisted server-side in a `sessions` table. New relationship: `USER ||--o{ SESSION : holds`.

## Key invariants added

- For every user at any time: at most 2 Active_Sessions and at most 1 per Device_Identifier.
- After a successful login the new Session is Active. Same-device Active_Sessions are always revoked as `DEVICE_REPLACED`.
- A `CONCURRENT_LIMIT` revocation happens only when 2 other-device Active_Sessions exist, and exactly the earliest by `(issuedAt, id)` is revoked.
- A failed login leaves all Sessions unchanged. A submitted Device_Identifier never affects another user.
